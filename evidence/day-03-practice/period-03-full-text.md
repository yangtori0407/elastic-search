# 3교시 실습 — 전문 검색 확장

## (공통) 문제 1 — 제공 코드로 여러 field 검색

```http
GET /products/_search
{
  "size": 5,
  "query": {
    "multi_match": {
      "query": "무선 이어폰",
      "fields": ["name", "description"]
    }
  }
}
```

### 결과 입력

- hits.total.value: 505

- 상위 3개 ID·name:
  1. P-00241 — SoundLab 프리미엄 무선 이어폰
  2. P-00305 — Auralis 실속형 무선 이어폰
  3. P-00529 — NeoTech 스마트 무선 이어폰

- 각 문서가 name·description 중 어디에서 의도와 연결되는가:
  1. name
  2. name
  3. name

- 상위 3개 관련/보류/무관 판정:
  1. 관련
  2. 관련
  3. 관련

## (공통) 문제 2 — field boost 직접 구현

### API 전체 입력

```http
GET /products/_search
{
  "size": 5,
  "query": {
    "multi_match": {
      "query": "무선 이어폰",
      "fields": ["name^3", "description"]
    }
  }
}
```

### 비교 결과

* 변경 전 상위 3개 ID:

  1. P-00241
  2. P-00305
  3. P-00529

* 변경 후 상위 3개 ID:

  1. P-00241
  2. P-00305
  3. P-00529

* 순위가 달라진 문서와 이유:
  → 상위 3개 문서의 순위는 달라지지 않았다. 기존 상위 문서들이 모두 `name`에 `"무선 이어폰"`을 직접 포함하고 있었기 때문에 `name^3`을 적용해도 서로 비슷하게 점수가 올라 순위 변화가 없었다.

* boost가 사용자 의도에 유리했는가:
  → 유리하다고 판단했다. 실제로 상위 문서의 `_score`가 약 `6.76`에서 `20.28`로 증가해 `name` 일치가 더 중요하게 반영된 것을 확인할 수 있었다. 다만 이번 상위 결과는 모두 `name`에서 동일하게 잘 일치했기 때문에 실제 순위 변화는 없었다.


## (공통) 문제 3 — 구문 검색 직접 구현

### API 전체 입력

```http
GET /products/_search
{
  "size": 5,
  "query": {
    "match_phrase": {
      "name": {
        "query": "무선 이어폰",
        "slop": 0
      }
    }
  }
}
```

### 결과 입력

* `hits.total.value`: 249

* 상위 문서 ID·name:

  1. P-00241 — SoundLab 프리미엄 무선 이어폰
  2. P-00305 — Auralis 실속형 무선 이어폰
  3. P-00529 — NeoTech 스마트 무선 이어폰

* 문제 1보다 결과가 같거나 줄어든 이유:
  → 문제 1의 `multi_match`는 `name`과 `description`에서 검색어와 관련된 문서를 폭넓게 찾는다. 반면 `match_phrase`는 `name`에서 `"무선 이어폰"`이라는 단어가 같은 순서로 바로 이어져 있는지를 확인하기 때문에 조건이 더 엄격하다. 따라서 검색 결과가 505건에서 249건으로 줄었다.

* 구문 의도에 맞지 않는 문서가 있는가:
  → 없다. 상위 문서 모두 상품명에 `"무선 이어폰"`이라는 표현이 그대로 들어 있어 검색 의도에 맞는다.


## (개인) 문제 4 — 여러 text field 검색

### API와 결과 입력

```http
GET /manga-books/_search
{
  "size": 5,
  "query": {
    "multi_match": {
      "query": "판타지",
      "fields": ["title", "description"]
    }
  }
}
```

* 사용자 질문·검색어:

  * 사용자 질문: 판타지와 관련된 만화를 찾고 싶다.
  * 검색어: `판타지`

* 선택 field와 역할:

  * `title`: 작품 제목에 검색어가 포함된 만화를 찾는다.
  * `description`: 제목에 검색어가 없어도 작품 설명이나 줄거리에서 판타지와 관련된 만화를 찾는다.

* 상위 3개 판정:

  1. MANGA-00004 — `판타지 만화 4` → **관련**
  2. MANGA-00008 — `판타지 만화 8` → **관련**
  3. MANGA-00009 — `판타지 만화 9` → **관련**

* query 선택 근거:

  * `판타지`라는 검색어가 작품 제목뿐 아니라 작품 설명에도 포함될 수 있기 때문에 `title`과 `description`을 동시에 검색할 수 있는 `multi_match`를 사용했다.


## (개인) 문제 5 — boost 가설 검증

### 선택한 가설

작품 설명보다 작품 제목에서 검색어가 일치하는 것을 더 중요하게 평가하면 사용자 검색 의도에 더 가까운 결과가 상위에 나타날 것이다.

### 변경 전 상위 3개

1. MANGA-00004 — 판타지 만화 4
2. MANGA-00008 — 판타지 만화 8
3. MANGA-00009 — 판타지 만화 9

### 변경 후 상위 3개

1. MANGA-00004 — 판타지 만화 4
2. MANGA-00008 — 판타지 만화 8
3. MANGA-00009 — 판타지 만화 9

### 개선/보류/악화 판정

보류

### 판정 근거

`title^3`을 적용한 뒤 상위 3개 문서의 순위는 바뀌지 않았다. 다만 `_score`는 약 2.35에서 약 7.05로 증가해 title 일치가 더 중요하게 반영된 것은 확인할 수 있었다. 이번 상위 결과들은 모두 title과 description에 `판타지`가 함께 포함되어 있어 boost를 적용해도 순위 차이가 발생하지 않았다.
